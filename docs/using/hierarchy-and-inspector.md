# Hierarchy and inspector

The hierarchy is the scene's tree of game objects: it adds an object under the selected one, deletes it, reorders it, drags it under another object or out of one, changes the class of its transform and picks the scene's camera, with a right click menu for each object. An object has an id, a name, an active switch, one transform that places it and a list of components that give it behaviour, as in Unity.

Every scene has exactly one root object, the first row of the tree. File > New Scene (Ctrl+N) asks for the transform of the root, a 2D scene (`Transform2D`), a 3D scene (`Transform3D`), a user interface (`RectTransform`) or an empty one with a plain `Transform`, and for the file's name. The root cannot be deleted, duplicated, moved or dragged: everything else lives under it, so a new object, a paste or a dropped asset goes inside it when nothing else is selected. A scene file with several top-level objects is opened with them under a new plain root named after the scene, which changes nothing about how they are placed, and is marked as changed until it is saved. A project whose scenes are still version 2, made of objects, is not opened: the editor offers to run the engine's `fried_import migrate-scenes`, which rewrites them and keeps the originals in `.fried/v2-backup`.

Each row shows an icon for the object's first component, or for its transform when it has none. A class the engine does not know the icon of, such as one of your own, takes the icon of the nearest class it extends, so a `SpriteRenderer` subclass looks like a sprite, and an inactive object is drawn dimmed. Rows alternate in shade, a line marks each level of nesting, the selected row has a bar on its left edge and the scene's camera carries a camera icon on its right. The plus button above the tree (or Ctrl+A) opens the Create New Object window, with a search, the empty objects (plain, 2D, 3D and UI) and the tree of component classes, and adds an object with the chosen component under the selected object, with the transform the component needs (Up and Down move the choice, and Enter or a double click adds it); F2 or a double click on a row renames the object, and Up and Down choose the row above or below, which the inspector follows, while Right opens a folded node and then goes into it and Left folds an open one and then goes up to its parent; the button beside it instances a scene. Change Transform Type in an object's menu opens the same window with the transform classes, and the scene's file name heads the tree, with a star while it has unsaved changes. Delete removes the selected object (it, Ctrl+D, Ctrl+C and Ctrl+V act on objects while the hierarchy or the Scene view has the keyboard), and the object's right click menu has Add Component, Activate or Deactivate, Move Up, Move Down and Use as Camera, which is for an object with a `Camera` or a `Camera3D`.

Ctrl+D duplicates the selected object with everything under it, right after it, with new ids and a name that none of its siblings has (`Enemy` gives `Enemy2`). Ctrl+C and Ctrl+V copy and paste: the copy goes to the system clipboard as text, so it can be pasted into another scene, even in another editor, and a paste lands next to the selected object, or in the scene when none is selected. All three are in the Edit menu and the object's right click menu, and each is one undo step.

The field beside the plus button filters the tree: it keeps the objects whose name or type contains the text, in blue, and the objects above them so each is seen in its place. Folds are ignored while there is text in it, and clearing it brings the tree back as it was.

A padlock at the end of a row locks the object: it shows when the pointer is over the row, and stays when the object is locked. A locked object is not picked by a click in the view, has no handles and is not moved there, so a background or a floor can be left alone while the objects over it are worked on; it is still chosen in the hierarchy and edited in the inspector. The locks belong to the editor and are remembered for each scene, and the scene file does not have them, so the game is not changed by them.

The inspector starts with the object's own fields, a checkbox for `active` and the name, and goes on with the transform and then one section for each component, in the order the object holds them. An object dragged under a rotated or scaled parent moves by the amount in its own coordinates that follows the pointer, and Ctrl+Z and Ctrl+Y undo and redo.

The layout of the panels is docked and is remembered in `layout.ini` in the editor's settings folder (`~/.config/fried-editor/`, or `%APPDATA%\fried-editor` on Windows).

In the inspector the transform and each component of the selected object has a bar with its icon and class, the components a cross at the end that removes them (one step to undo), and the fields under it are a name on the left, written as words (`scaleX` reads Scale X), and an editor on the right. The x and y of an object, and any fields named like `scaleX` and `scaleY` (and z when there is one), are shown as one row of small fields, each with its axis letter in red, green or blue; each axis is still its own field and its own undo step.

A field that the scene sets to something other than its default shows a revert arrow at the end of its name, as in Godot. A click takes the field out of the scene's data so the default applies again (for an object that instances a scene, the value of the instanced scene), as one step to undo; the row of x and y, or of scale, has one arrow for both axes.

A field that holds a file, such as the texture of a sprite or the font of a label, can be filled three ways: by typing the reference (`game/sprite.png`, and `engine/NunitoSans.ttf@16` for a font with its size), by dragging the file from the Assets tab onto it, or with the magnifier button at its end. The button opens a list of the project's files of the kind the field takes, images for a texture and fonts for a font, with a thumbnail for each, a search field and a `None` entry that clears the field. The one in use is marked, and choosing a font keeps its size.

## Components

Add Component, at the end of the inspector and in the object's menu, opens a list of the component classes that fit the object, found by typing: a `SpriteRenderer` needs a `Transform2D`, so it is not offered for an object with a `RectTransform`. The new component has the defaults of its class, goes last in the object's list and is one step to undo, as removing one is, which puts it back where it was. An object may have several components of a class, and a field that points at one of them names the object. Change Transform Type... gives the object a transform of another class and keeps the values the new class also has; the running game does not get that edit until the next run. An object that instances a scene shows the components of that scene, and what the instance sets is written in the scene file as an override of the component of that class.

## Instancing a scene

Window > Undo History lists the steps of the open scene's undo stack, from Original to the last one done, and a click on a step goes to the scene as it was after it, undoing or redoing what lies between. The steps not done are dimmed and can still be redone. While the game runs, the list starts where the play began.

The text of a label and the cells of a tilemap are text areas that show their lines, and apply when the area loses focus, so typing in one is one step of undo. A tilemap's cells are one line for each row of the map with the number of each tile separated by spaces, 0 for no tile; the Scene view shows the map as it is typed, and its box is the whole map. There is no painting tool yet.

A scene of the project can be an object of another, as a prefab is in Unity. The hierarchy's add menu (Instance Scene), an object's menu (Instance Child Scene) and the Assets tab (Instance in Scene, or dragging the file onto the Scene view or onto an object) add one. An instance is one row with a scene icon, and a button on it opens the instanced scene in its own tab. Its fields are the ones of the instanced scene's root: what the instance does not set shows the value the instanced scene has, and what it sets overrides it. Any scene can be instanced, since each has one root, and one that would end up containing itself is refused. The Issues tab lists an instance whose scene is gone, or would contain itself, and offers to remove the instance or to choose another scene for it. The scene view shows an instance as one node, with the box of everything inside it, and a scene's CanvasLayer, which the game draws in screen space, at the origin of the world, where it can be picked.
