# Assets and issues

The Assets dock lists the images, fonts, sounds, scenes and scripts of the project and of the engine: drag an image onto the view for a new Sprite, onto a Sprite to change its texture, or a font for a new Label; a double click drops it in the middle.

The dock has the folders on the left, a tree that starts at the three roots, `game` for the project's own files, `engine` for the engine's and `src` for the project's source, where its scripts are, and the folder that is open on the right. When the panel is too narrow for two columns it shows one tree that holds both the folders and their files, as Godot does, and the controls move to a line of their own; the button at the end of the controls chooses between automatic, the tree beside the files or the files only, and between a grid, a list or automatic. The line above shows where it is, and each name in it goes back to that folder; the search, the kind of file, the thumbnail size and the list switch are at the right end of that line. A double click on a folder opens it, the field searches everything below the open folder, and so does the kind list (All types, Images, Fonts, Audio and Scenes). The slider sets the size of the thumbnails, the button at its side shows the files as a list, and the line between the panes can be dragged to change the width of the tree. The folder that was open is remembered for each project.

The project's own files can be managed from the dock. A right click on a file or a folder offers Rename, Duplicate, Delete and New Folder, and a right click on the empty space makes a folder in the one that is open; a new folder is shown even while it is empty. Dragging a file or a folder onto a folder, in the tree or in the content, moves it. Scene files hold references to assets, so a move or a rename first saves the open scenes, rewrites the references in every scene of the project and reads the scenes again, which drops their undo history; the status bar says how many references followed. A delete lists the scenes that still use the file and asks first. References in code, such as a path written in a Haxe file, are not found and stay as they were. Clicking a file or a folder chooses it, and F2 renames what is chosen while the dock has the keyboard. The engine's files are read only, and the scenes keep their place in `game/scenes`, where the game finds them by name, so they cannot be moved, renamed or deleted from here.

The `src` root is the Haxe source of the game, and a double click on a script opens it with the program the system has for `.hx` files. New Script, in the menu of a file or a folder and in the one of the empty space, asks for a name and for the class it extends, which can be any class the editor lists, the engine's or the game's, and writes a node class with `ready()` and `update()` to fill in under `src/nodes`, the folder where scenes find a game's nodes. The editor knows a new class only after the player is built again (Run, Rebuild player), and then it is in the Create New Node window. A script is a class, so its name starts with a capital letter and has only letters, digits and underscores. Moving a script into another folder rewrites its `package` line to match, renaming it renames the class that had its name and the type of the nodes in the scenes that used it, and duplicating one names the copy `NameCopy` and its class with it. Other Haxe files that mention the class are not touched, and the compiler lists them.

The Issues tab checks the project's assets against the platform being previewed: textures over 1024 pixels on the 3DS and DS, DS audio that is not mono PCM WAV, audio on the fx-CG50, a project that does not fit its 2 MB, and an image in `sce_sys/` that is not a palette PNG, which the Vita's installer refuses. An issue with a fix has a button, and the file as it was is kept in `.fried-editor/originals/` in the project.
